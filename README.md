# ERP workflow replica

A React + Tailwind/Vite frontend and a small Python/SQLite API that build out a same-workflow finance replica from read-only ERP screen references. The current slice includes the finance navigation groups, revenue and expense dashboard, Collection Receipt listing and entry, four-level Chart of Accounts, Journal/Voucher posting, Trial Balance, Balance Sheet, Profit and Loss and Profit and Loss Comparison, account Ledger (detail and summary), Consolidated Ledger, Collection History, Cheque In Hand lifecycle log, and Customer Statement. All displayed people, organizations, accounts and transactions are fictional sample data. Menu items without a mapped screen currently open an explicit placeholder.

## Run

Install frontend dependencies with `npm install`. Start the API with `npm run api` in one terminal and the UI with `npm run dev` in another. The API uses only Python's standard library and listens on `127.0.0.1:8002` so it can run alongside an older local demo API without replacing it. It creates and uses `database/demo_erp_replica.sqlite`; the existing `database/demo_erp.sqlite` is left untouched.

## Data model

`database/schema.sql` is a standalone SQLite schema for organizations, users, a four-level chart of accounts (main account, sub account, account head and transaction account), customers, stations, cost-center heads and cost centers, receipts, deposit splits, cheques and immutable cheque events, journal entries, approvals, audit events, and a posted-journal customer statement view. The attached COA export was inspected read-only to understand its columns and hierarchy; its account data was not copied into the demo. The API initializes a dedicated `database/demo_erp_replica.sqlite` file with fictional records and reuses it on later starts; the existing finance database is not selected by the API. Receipt saves remain drafts and require deposit splits to match receipt net. Journal/Voucher posting is limited to balanced entries against transaction accounts. The customer statement and Trial Balance read posted journal lines; Trial Balance supports date, station and cost center filters. Ledger supports transaction-account, date, station, cost-center and currency filters, selectable columns, and detail/summary views. Consolidated Ledger reads posted journal lines across the selected account subtree and requested account level, with station/date, cost-center head/center, account-head type, currency and employee filters, detail/summary views, zero-entry display and selectable export columns. Collection History reports fictional receipts by customer with station/cost-center/date filters, cheque details and totals. Bank Balance groups posted cash/bank asset balances by type and shows opening, receipts, payments and closing amounts with company/station/cost-center/group/date filters, Cash/Bank toggles, export, print and fullscreen actions. Balance Sheet groups as-of posted ledger balances into the observed six report sections, with station/cost center filters and an explicit PKR demo base currency. Profit and Loss calculates its statement lines from posted income and expense journals for a selected date range and optional station/cost-center filters. Profit and Loss Comparison shows the same statement rows for two date ranges and calculates the difference as Range 2 minus Range 1. Station/Cost Center Wise P&L mirrors the pivot layout with Note/Account/Code rows and switches its columns between station and cost-center masters. It includes account-level journal totals, keeps unassigned journal lines in their own column, and exports CSV.

## Scope

This remains a finance-module slice of the larger ERP. Balance Sheet currently maps all demo assets and liabilities to current categories because the fictional chart has no non-current or long-term transactions yet; it shows a balance check to expose any unbalanced demo posting. Profit and Loss assigns accounts to the visible statement rows using account types and account-name categories; the demo COA has no sub-cost-center master, so that visible filter is disabled. Collection Receipt now has Cash & Bank, Cheque Receipt and Cheque Return tabs. The return panel reads eligible fictional cheques and records selected returns through one atomic batch, with date, transfer medium, remarks, totals and audit events. Cheque clearing posts a bank/cheques-in-hand transfer; bounce or customer return restores the receivable; and a replacement after bounce/return reapplies receivable. Physical return after a recorded bounce remains a custody event without another journal. These lifecycle journals are atomic, balanced, and appear in customer statements where a customer receivable is involved. The API rejects clearing or bouncing cheques whose collection receipt has not posted. Receipt workflow supports draft, pending, approved and posted states. Posting creates one balanced source-linked journal atomically: deposit accounts are debited, discounts are debited to an active discount expense account, and each customer receivable is credited for gross. Finance menu entries beyond the implemented screens still need read-only screen references and workflow implementation. The live ERP, its database and its financial records are never used by this app.

All Transaction Report follows the live Finance report structure with date, company, currency, station, cost-center, detail-account and voucher-type filters. The report reads posted journal lines only and provides search, totals, print and CSV export from fictional demo records.

Expense Report follows the live report filter and column layout with Detail and Summary views. It reads posted demo expense journal lines, joins the account-head hierarchy and station/cost-center masters, and supports search, CSV export and print.

Receipt Report mirrors the live filter and table workflow, including Detail/Summary, date, station, cost-center, account and employee filters. It reads customer-linked posted receipt journal lines from the fictional demo database and supports search, totals, print and CSV export.

Collection Receipt listing now mirrors the live column structure, with status/date filters, pagination, export and a detail panel. Its entry form loads fictional local masters and saves customer, station, cost center, employee, invoice, currency and deposit split fields. Cheque Receipt also saves the Call, Locker and Cheque Type header selections, each cheque’s currency date and signatory, and uses the receipt’s single exchange rate consistently for accounting. Cheque deposit splits are restricted and revalidated at save, submission and posting to the active Cheques In Hand account (1120), matching subsequent clear, bounce and return journals. A cheque receipt cannot be submitted or posted without a cheque still in custody; a returned draft cheque can be replaced or the draft voided after custody is resolved. Replacement-cheque entry captures its new cheque date, currency date, bank and signatory while retaining the original amount, customer, currency and locker. Load Invoices finds open balances from posted local invoice journals, subtracts prior posted receipt allocations, and verifies invoice/customer/currency and remaining balance again when saving and posting. Server-side checks validate ownership, require positive receipt/deposit amounts, and balance deposit allocations to the receipt net before an atomic draft save. Deposit splits are allocated to customers, with each customer’s deposit total checked against that customer’s net receipt. Cheque records retain the selected customer link, including multi-customer receipts. Drafts can be opened and edited; the update replaces receipt lines and deposit splits in one transaction. Editing is blocked after any journal link or cheque lifecycle event so an accounting or custody history cannot be silently rewritten. Drafts can be submitted, pending receipts approved, approved receipts posted, and unsubmitted drafts voided when no cheque custody record exists. Posting checks for active customer receivable accounts, deposit/net agreement, and a balanced journal before committing status, journal, approval and audit records together.

Payment is now an implemented Finance workflow. It saves payee and cash/bank source lines as drafts, validates that source amounts equal net payment, and posts a balanced journal atomically. Cheque payments require a cheque book, instrument number and date. Discounted payments credit the fictional Discount Received transaction account.
Expense is now an implemented Finance workflow with cash/bank source selection, expense detail lines, fictional draft records, submit/approve/reject transitions, and balanced journal posting after approval. Amounts are stored in the selected currency and converted using the saved header rate.

Cheque Receipt mirrors the live tab with its own bank, currency date/rate, cheque number/date/amount and signatory grid; banks are fictional replica-only master data. Set `ERP_REPLICA_PORT` to choose another local API port and `VITE_API_BASE` to point the frontend at it when the default port is occupied.
Cash & Bank entry now follows the live single-grid layout. Tender lines retain their currency dates in the replica database, use the selected customer and header dimensions, and allocate gross less discount to the chosen cash/bank account.
